## 1. Tóm tắt điều hành

AI Challenge TP.HCM 2026 là cuộc thi thường niên về trí tuệ nhân tạo do Thành phố Hồ Chí Minh tổ chức, hướng đến việc thúc đẩy học tập, nghiên cứu và ứng dụng AI phục vụ đô thị thông minh và các bài toán thực tiễn.

Năm 2026, trọng tâm cuộc thi là:

> **Phát triển giải pháp Trợ lý ảo thông minh hỗ trợ phân tích và truy xuất thông tin chuyên sâu trong dữ liệu lớn multimedia gồm hình ảnh, âm thanh và văn bản.**

Cuộc thi có định hướng tương tự các cuộc thi quốc tế:

- **Lifelog Search Challenge (LSC)**
- **Video Browser Showdown (VBS)**

Điểm quan trọng của mùa 2026:

- Không chỉ là bài toán tìm kiếm video/hình ảnh đơn giản.
- Cần xây dựng hệ thống **multimodal retrieval assistant**.
- Có 2 hình thức thi được định hướng:
  - Hình thức truyền thống: người dùng sử dụng công cụ trợ lý ảo của đội.
  - Hình thức tự động: thử nghiệm thi tự động giữa các trợ lý ảo của các đội.
- Khuyến khích sử dụng:
  - Large Vision Language Model (LVLM)
  - AI tạo sinh
  - Xử lý dữ liệu lớn
  - Xử lý dữ liệu đặc thù Việt Nam: ngôn ngữ, âm thanh, hình ảnh
  - Tương tác thông minh giữa các module/hệ thống

## 8. Hai hình thức thi năm 2026

### 8.1. Hình thức truyền thống

Người dùng sử dụng công cụ Trợ lý ảo thông minh của nhóm mình để xử lý truy vấn thông tin từ kho dữ liệu multimedia.

#### Hàm ý kỹ thuật

Đội thi cần có:

- Giao diện truy vấn nhanh.
- Hiển thị kết quả dễ quan sát.
- Preview video/frame/timeline.
- Bộ lọc theo object, text, OCR, audio/transcript, metadata.
- Hotkey để thao tác nhanh.
- Cơ chế xem các frame/segment lân cận.
- Cơ chế giữ lại candidate nghi ngờ.
- Workflow vận hành rõ cho operator.

### 8.2. Hình thức tự động

Hội thi thử nghiệm đưa thêm hình thức thi tự động giữa các Trợ lý ảo thông minh của các nhóm.

#### Hàm ý kỹ thuật

Đội thi cần có:

- Agent hiểu truy vấn.
- Agent tự phân loại dạng truy vấn.
- Agent tự chọn module xử lý phù hợp.
- Agent gọi các công cụ retrieval: visual, audio, OCR, text, metadata.
- Agent rerank kết quả.
- Agent đánh giá confidence.
- Agent tự quyết định trả kết quả/submission.
- Hệ thống log được quá trình ra quyết định để debug.

## 9. Năng lực kỹ thuật cốt lõi cần xây dựng

### 9.1. Visual retrieval

Dùng để tìm kiếm:

- Cảnh trong video.
- Object.
- Người/vật/địa điểm.
- Hành động.
- Màu sắc, bố cục, bối cảnh.
- Frame/shot tương tự với ảnh hoặc video mẫu.

Công nghệ gợi ý:

- CLIP
- SigLIP
- EVA-CLIP
- OpenCLIP
- FAISS
- Qdrant/Milvus nếu cần vector DB dạng service

### 9.2. Audio understanding / ASR

Dùng để truy xuất theo:

- Lời nói trong video.
- Nội dung phát biểu.
- Từ khóa tiếng Việt.
- Chủ đề được nhắc đến trong audio.

Công nghệ gợi ý:

- Whisper large-v3 / turbo
- Model ASR tiếng Việt chuyên dụng nếu cần
- Transcript segmentation
- Search theo keyword và embedding

### 9.3. OCR / Text-in-video retrieval

Dùng để tìm:

- Chữ trên màn hình.
- Biển hiệu.
- Slide trình chiếu.
- Tên tổ chức/sự kiện.
- Caption/bảng biểu trong video.

Công nghệ gợi ý:

- PaddleOCR
- VietOCR
- EasyOCR
- Fuzzy matching
- BM25 search
- Text embedding search

### 9.4. Captioning / Scene description

Dùng để tạo mô tả cho frame/shot/video segment.

Công nghệ gợi ý:

- Qwen2.5-VL
- InternVL
- LLaVA-family
- BLIP/BLIP-2
- Florence-family

Caption nên mô tả:

- Người/vật thể chính.
- Hành động.
- Bối cảnh.
- Quan hệ không gian.
- Màu sắc nổi bật.
- Chữ nhìn thấy nếu có.
- Dấu hiệu sự kiện.

### 9.5. Text search / Semantic search

Dùng cho:

- Caption.
- Metadata.
- Transcript.
- OCR text.
- Tags/concepts.
- Query expansion.

Công nghệ gợi ý:

- Elasticsearch
- OpenSearch
- Tantivy
- PostgreSQL full-text search
- bge-m3
- multilingual-e5
- jina multilingual embeddings

### 9.6. Reranking

Dùng để sắp xếp lại top candidates từ nhiều nguồn.

Công nghệ gợi ý:

- Cross-encoder reranker.
- bge-reranker.
- LLM/LVLM-based verification ở top-K.
- Rule-based boosting theo query type.

### 9.7. Agent orchestration

Dùng cho hình thức tự động và trợ lý ảo thông minh.

Năng lực cần có:

- Classify query type.
- Extract constraints.
- Generate search plan.
- Call retrieval tools.
- Merge/rerank results.
- Verify evidence.
- Return answer.
- Log reasoning trace dạng an toàn/kỹ thuật.

## 10. Kiến trúc hệ thống khuyến nghị

```text
User / Judge Query
        |
        v
Query Understanding Layer
- intent classification
- Vietnamese normalization
- entity extraction
- query expansion
- modality routing
        |
        v
Retrieval Orchestrator
- visual search
- caption/text search
- OCR search
- ASR/transcript search
- metadata search
- temporal search
        |
        v
Candidate Fusion + Reranking
- weighted fusion
- cross-encoder rerank
- LVLM verification
- temporal consistency
- diversity control
        |
        v
Answer Layer
- video ID
- timestamp
- frame/segment
- confidence
- evidence
        |
        v
Human UI / Auto-Agent Submission
```

### 10.1. Nguyên tắc kiến trúc

1. **Retrieval Core dùng chung cho UI và Agent**
   - Không xây 2 hệ thống rời.
   - Human UI và Auto-Agent cùng gọi API backend.

2. **Offline-first nếu có thể**
   - Chung kết có thể giới hạn internet/API.
   - Nên chuẩn bị khả năng chạy local.

3. **Index-based, không inference nặng ở runtime**
   - Các tác vụ nặng như embedding, OCR, ASR, caption nên chạy offline trước.
   - Runtime chủ yếu là search, rerank nhẹ, preview.

4. **Latency là chỉ số sống còn**
   - Thi live cần tốc độ phản hồi rất nhanh.
   - UI chậm có thể khiến đội mất điểm dù model tốt.

5. **Có logging đầy đủ**
   - Không log thì không debug được.
   - Cần log query, search plan, top candidates, score, submit, lỗi.

## 14. Query types cần chuẩn bị

| Query type | Ví dụ | Module chính |
|---|---|---|
| Textual visual search | "Tìm cảnh một người mặc áo đỏ đứng cạnh xe buýt" | Visual + caption + object |
| Visual KIS | Tìm frame/segment giống ảnh/video mẫu | Visual embedding |
| Audio/content query | "Đoạn người phát biểu về chuyển đổi số" | ASR + caption + visual |
| OCR query | "Cảnh có chữ 'Ủy ban nhân dân'" | OCR + visual |
| Event query | "Một buổi lễ khai trương có cắt băng" | Caption + visual + object |
| Temporal query | "Sau cảnh người bước vào phòng họp là gì?" | Timeline + segment navigation |
| Q&A multimedia | "Người trong đoạn video đang nói về chủ đề gì?" | ASR + RAG + summarization |
| Hybrid query | "Người đứng trên sân khấu nói về AI, phía sau có màn hình xanh" | ASR + OCR + visual + caption |
| Ambiguous query | "Tìm cảnh giống một sự kiện công nghệ" | Query expansion + hybrid search |

## 15. Fusion scoring gợi ý

Không nên dựa vào một nguồn duy nhất. Nên dùng hybrid fusion.

Ví dụ công thức tổng quát:

```text
final_score =
  visual_weight  * visual_score  +
  caption_weight * caption_score +
  asr_weight     * asr_score     +
  ocr_weight     * ocr_score     +
  object_weight  * object_score
```

Trọng số nên thay đổi theo query type:

| Query type | Visual | Caption | ASR | OCR | Object |
|---|---:|---:|---:|---:|---:|
| Cảnh/hình ảnh | 0.45 | 0.25 | 0.05 | 0.05 | 0.20 |
| Lời phát biểu | 0.15 | 0.20 | 0.50 | 0.05 | 0.10 |
| Chữ trên màn hình | 0.10 | 0.15 | 0.05 | 0.60 | 0.10 |
| Sự kiện tổng hợp | 0.30 | 0.30 | 0.20 | 0.10 | 0.10 |
| Query mơ hồ | 0.35 | 0.35 | 0.10 | 0.05 | 0.15 |

## 16. Auto-Agent design

### 16.1. Agent loop đề xuất

```text
Input query
  -> classify query type
  -> extract constraints
  -> generate search plans
  -> run parallel retrieval
  -> merge candidates
  -> rerank
  -> verify top candidates
  -> compute confidence
  -> return answer/submission
```

### 16.2. Query parser output đề xuất

```json
{
  "query_type": "hybrid",
  "main_intent": "find_video_segment",
  "visual_constraints": {
    "objects": ["person", "microphone", "screen"],
    "actions": ["speaking", "presenting"],
    "scene": ["conference", "stage"]
  },
  "audio_constraints": {
    "keywords": ["chuyển đổi số", "giáo dục"]
  },
  "text_constraints": {
    "ocr_keywords": ["hội nghị", "AI", "TP.HCM"]
  },
  "temporal_constraints": {
    "before": null,
    "after": null
  },
  "search_strategy": ["asr", "caption", "visual", "ocr"]
}
```

### 16.3. Confidence policy

Agent chỉ nên auto-submit khi:

- Top-1 score cách top-2 đủ xa.
- Nhiều modality cùng đồng thuận.
- Evidence từ caption/OCR/ASR/visual khớp.
- Timestamp nằm trong segment hợp lý.
- Reranker hoặc verifier xác nhận.

Nếu confidence thấp:

- Trả top-3/top-5.
- Refine query 1-2 lần.
- Dùng fallback search.
- Nếu thi truyền thống, đẩy candidate sang UI cho operator quyết định.

## 22. Evaluation metrics nội bộ

Dù BTC chưa công bố metric chi tiết, đội nên tự đo:

| Metric | Ý nghĩa |
|---|---|
| Recall@10 | Kết quả đúng có nằm trong top 10 không |

| Query trung bình | <90s | <45s |
